# werstakoffAiConstructor — AGENTS.md

Единый источник правды для разработки. Читать целиком перед любой задачей.
Язык интерфейса и промптов — русский. Код, имена переменных, коммиты — английский.

---

## 1. Что делаем

AI-конструктор подбора металлической мебели «Верстакофф» для клиента:

1. Клиент загружает **одно** фото помещения.
2. **Jev** проверяет: это помещение, есть пол/стены, одна стена ≥ 2 м, нет людей/неприемлемого контента. Если нет — «Перезагрузите фотографию» и стоп.
3. В фоне **image-edit** убирает с фото всю мебель, мусор, людей — остаются пустые стены, окна, двери, пол.
4. **Jev** по очищенному фото даёт диапазоны габаритов и признаки (окна, двери, выступы, карманы).
5. Мастер задаёт вопросы; клиент подтверждает/вводит точные размеры.
6. Детерминированный подбор + 2D-раскладка по каталогу, затем LLM-ранжирование и объяснение.
7. Показываем список товаров и запускаем **3 превью-варианта** расстановки (1K, с водомаркой).
8. Клиент правит текстом и/или в мастере. До **4 раундов правок по 2 варианта**. Jev классифицирует правку, LLM меняет состав/расстановку, идёт перегенерация.
9. Финал: **4K** из согласованного превью, PDF-заказ, страница заказа со скачиванием картинки и PDF.
10. Заказ появляется **в админке** (email/CRM пока не отправляем).

Жёсткий лимит стоимости AI на сессию: **60 ₽**. При достижении — остановка с понятной ошибкой.

## 3. Проверенные факты по Polza.ai

Токен: `POLZA_TOKEN` в `.env` (не коммитить). Base URL: `https://polza.ai/api/v1`.

### 3.1 Jev — мультимодальный классификатор

- Модель: `typesafe/jev`, эндпоинт `POST /systemone`.
- **Видит изображения.** Проверено на `jev-1.14-20261014`.
- Формат состояния — массив частей:

```json
{
  "model": "typesafe/jev",
  "state": [
    { "type": "text", "text": "Фотография помещения клиента." },
    { "type": "image_url", "image_url": { "url": "https://.../photo.jpg" } }
  ],
  "questions": {
    "is_room": { "type": "noul", "instructions": "На изображении внутреннее помещение?" },
    "room_type": {
      "type": "choice",
      "instructions": "Что это за помещение?",
      "criteria": { "warehouse": "Склад", "workshop": "Цех", "other": "Другое" }
    }
  }
}
```

- Ответ: `answers.<name>.noul` (0..1), либо `.choice` + `probabilities` + `confidence`, либо `.score`.
- **Ограничение `state`: 400 000 символов.** Передавать изображения только по URL (MinIO), не base64.
- Заголовок `TypeSafe-Danger-Zone-Images: true` не обязателен, но отправляем.
- Jev **не пишет свободный текст** и **не возвращает числа**. Только да/нет, выбор, шкала.
- Цена: 17.36 ₽/млн входных токенов. Фактический вызов с фото 900px — ~0.04 ₽.
- Для точных размеров использовать `choice` с диапазонами, точные числа вводит клиент.

### 3.2 Модели (цены на момент проверки)

| Задача | Модель | Цена |
|---|---|---|
| Валидация фото, признаки, диапазоны | `typesafe/jev` | ~0.04 ₽ |
| Классификация правок, интентов | `typesafe/jev` | ~0.005 ₽ |
| Подбор/ранжирование/объяснение | `openai/gpt-5-nano` или `google/gemini-2.5-flash-lite` | ~0.3 ₽ |
| Очистка фото (inpaint) | `google/gemini-3.1-flash-lite-image` | 2.9 ₽ |
| Превью 1K | `google/gemini-nano-banana-2.1` (`image_resolution: 1K`) | 3 ₽ |
| Финал 4K | `google/gemini-nano-banana-2.1` (`4K`) | 6.75 ₽ |
| Апскейл (резерв) | `topaz/image-upscale` | 7.5 ₽ |

Медиа-API: `POST /media` → `{id, status}` → `GET /media/{id}` до `completed`, URL в `data.url`.
CDN Polza хранит результат 7 дней — **скачивать сразу**.
Стоимость приходит в `usage.cost_rub` — логировать каждый вызов.

### 3.3 Бюджет сессии (60 ₽)

| Шаг | Кол-во | Стоимость |
|---|---|---|
| Jev: валидация фото | 1 | 0.05 ₽ |
| Очистка фото | 1 | 2.90 ₽ |
| Jev: признаки и диапазоны | 1 | 0.05 ₽ |
| LLM: подбор и текст | 1 | 0.30 ₽ |
| Превью 1K | 3 | 9.00 ₽ |
| Правки: 4 раунда × 2 | 8 | 24.00 ₽ |
| 4K финал | 1 | 6.75 ₽ |
| **Итого** | | **43.05 ₽** |
| Резерв на ретраи | | **16.95 ₽** |

Правила:
- Перед каждым платным вызовом проверять `spent + estimated <= 60`.
- `ai_usage` пишется на каждый вызов: модель, шаг, токены, `cost_rub`, длительность.
- При превышении — `BUDGET_EXCEEDED`, пользователю: «Лимит генераций для этой сессии исчерпан».
- Ретраи: 1 повтор при 5xx/timeout, только если хватает резерва.

Монорепо, pnpm workspaces, Node.js 22, TypeScript strict, ESM.

```
werstakoffAiConstructor/

│   ├── core/         # домен, статусы, zod-схемы, ошибки, типы задач
│   ├── db/           # Prisma schema, клиент, миграции, seed
│   ├── ai/           # клиент Polza, промпты, cost guard, Jev, рендеры
│   ├── catalog/      # импорт items.json, нормализация, скрапинг сайта
│   ├── packing/      # 2D-раскладка, проверка проходов
│   ├── pdf/          # генерация PDF
│   ├── storage/      # MinIO/S3: put/get/delete, подписанные ссылки
│   └── queue/        # BullMQ + Redis pub/sub для SSE
├── infra/
│   ├── docker/       # Dockerfile.node, Dockerfile.web, nginx.conf
│   └── assets/       # шрифты DejaVu, логотип
├── items.json        # исходник каталога (копируется в образ)
```

### Сервисы docker-compose

| Сервис | Назначение |
|---|---|
| `postgres:16` | основная БД |
| `redis:7` | BullMQ |
| `minio` | фото, очищенные, рендеры, PDF, картинки каталога |

## 6. Импорт каталога

Источник: `items.json` (2890 позиций, 105 секций, 180 свойств).

### 6.1 Нормализация габаритов

Порядок источников:
1. `props.A1` — строки вида `800x600x450`, `850х1000х714`, `(800-1000)x1000x700 мм`.
2. `props.stel11/12/13` — числовые мм (высота/глубина/ширина в разных сериях).
3. `props.V4/V5/V6` — числовые мм.
4. Название: `2000х1240х1005`, `ВхШхГ 855x1196x696`, `1700х2500х600`.

Правила:
- Приводить `х` (кириллица) к `x`, убирать `мм`, пробелы, диапазоны брать по максимуму.
- Определять порядок: если в названии есть `ВхШхГ` — высота, ширина, глубина; иначе для стеллажей `ДхШхВ`, для столов `ШхГхВ`. Хранить `width_mm`, `depth_mm`, `height_mm`.
- Если габарит не извлекается — `has_dimensions = false`.
- Валидация: 100 ≤ размер ≤ 10000 мм, иначе не доверять.

### 6.2 Группировка «модель → варианты»

- Ключ модели: серия + артикул-префикс без цвета/оснащения/размера.
- Пример: `Стеллаж металлический CRG 2000х1240х1005 мм. P/Z3/У` → модель `CRG`, вариант с конкретной конфигурацией.
- Варианты различаются цветом (`P9`), оснащением (`V*`), размером.
- В подборе участвуют варианты, в UI показываем группу с выбором варианта.

### 6.3 Категории

- 105 `section` в `items.json` **без названий**.
- Скрапим `https://werstakoff.ru/catalog/` и страницы товаров (`/catalog/item{id}.html`) — хлебные крошки дают путь.
- Верхний уровень сайта: Верстаки, Тележки, Шкафы, Столы-верстаки, Стеллажи, Роллетные шкафы, Тумбы, Сварочные столы, Антистатические столы, Передвижные мастерские, Прочее.
- Сопоставление `section → category` сохраняем в БД; ручная правка доступна в админке.
- Скрапинг — отдельная команда `pnpm catalog:import`, кешировать HTML в `.cache/scrape/`.

### 6.4 Картинки

- `picture` — путь с сайта: `https://werstakoff.ru{path}`.
- Скачивать в MinIO `catalog/{external_id}.jpg`, ресайз до 1200px, WebP + JPEG.
- 404/битый файл → `infra/assets/placeholder.svg`.
- Не хранить внешние URL в UI.

### 6.5 Доступность

- `price_rub = 0` → `is_active = false`, в подбор не попадает.
- `has_dimensions = false` → не участвует в геометрии, может показываться с пометкой «размеры по запросу».
- Дубликаты по имени — объединять в модель, не удалять варианты.

## 7. Вопросы мастера

Источник — анализ каталога (стеллажи, верстаки, столы, тележки, шкафы, тумбы, сварочные и антистатические столы).

| # | key | Тип | Варианты |
|---|---|---|---|
| 1 | `room_purpose` | choice | склад/архив, производственный цех, мастерская/сервис, гараж/автосервис, учебный класс, офис/лаборатория, другое |
| 2 | `storage_type` | multi | инструмент и оснастка, запчасти/метизы, документы/архив, тяжёлые грузы, СИЗ/одежда, крупногабарит, ничего (только рабочие места) |
| 3 | `shelf_load` | choice | до 120 кг, до 185 кг, до 450 кг, до 700 кг, больше 700 кг |
| 4 | `workplaces` | choice | 0, 1–2, 3–5, 6–10, больше 10 |
| 5 | `zones` | multi | верстаки/столы, стеллажи, шкафы, инструментальные тележки, тумбы, сварочный стол, антистатическая зона, монтажный стол |
| 6 | `ceiling_height` | choice | до 2.5 м, 2.5–3 м, 3–4 м, больше 4 м |
| 7 | `floor_type` | choice | бетон, плитка, металл, дерево, другое |
| 8 | `antistatic` | noul | нужна ли защита от статики (электроника) |
| 9 | `color` | choice | серый RAL 7047, синий RAL 5015, чёрный RAL 9011, любой |
| 10 | `budget` | choice | до 100 000 ₽, 100–300 тыс., 300–700 тыс., больше 700 тыс. |
| 11 | `delivery_assembly` | noul | нужна доставка и сборка |
| 12 | `priority` | choice | максимум хранения, максимум свободного места, баланс |

## 8. Подбор и раскладка

### 8.1 Фильтр

1. Категории по `zones` и `storage_type`.
2. `shelf_load` → фильтр по нагрузке на полку (`stel2`, `P*`).
3. `antistatic` → только антистатические серии.
4. `color` → совпадение `P9`/`V11`, иначе нейтральный.
5. `budget` → сумма ≤ верхней границы.
6. Габариты: высота ≤ потолка, длина/глубина влезают в стену.

### 8.2 Раскладка (`packages/packing`)

- Комната — прямоугольник, стены — сегменты; двери/окна — запретные зоны.
- Отступы: 100 мм от стены, 800 мм проход между рядами, 600 мм перед дверью.
- Стеллажи и шкафы — вдоль стен, верстаки — рядом, тележки/тумбы — в свободных местах.
- Сетка 10 мм, поворот на 90° разрешён.
- Результат: координаты `{variant_id, x, y, rotation, qty}` + метрики (заполнение, свободная площадь).
- Жадный алгоритм по убыванию площади + 3 варианта порядка для разных превью.

### 8.3 Ранжирование

- Детерминированный score: соответствие категорий, нагрузка, бюджет, заполнение, цвет.
- LLM получает top-20 и возвращает порядок + короткие объяснения (structured output, zod).
- LLM **не придумывает товары** — только выбирает из переданных id.

## 9. AI-пайплайн

Все вызовы — через `packages/ai/client.ts`:
- таймаут 300 с, polling 3 с;
- лог в `ai_usage`;
- проверка бюджета до вызова;
- сохранение результата в MinIO сразу;
- ошибки → `ai_jobs.error`, пользователю понятный текст.

### 9.1 Валидация фото (Jev)

Вопросы: `is_room`, `has_floor`, `has_wall_2m`, `has_people`, `is_inappropriate`, `room_type`, `width_range`, `depth_range`, `height_range`, `clutter_level`.
Порог: `is_room ≥ 0.7 && has_floor ≥ 0.7 && has_wall_2m ≥ 0.6 && has_people ≤ 0.3 && is_inappropriate ≤ 0.2`.
Иначе `rejected` + сообщение «Перезагрузите фотографию».

### 9.2 Очистка (image-edit)

Модель `google/gemini-3.1-flash-lite-image`, 1K, референс — оригинал.
Промпт: убрать всю мебель, коробки, мусор, людей, провода; сохранить геометрию стен, окна, двери, пол, потолок, освещение, ракурс; ничего не добавлять.
Результат — `cleaned`, используется как база для всех рендеров.

### 9.3 Признаки помещения (Jev)

По очищенному фото: диапазоны ширины/глубины/высоты, наличие окна/двери, выступы/карманы, тип пола.
Мастер показывает диапазоны как подсказку, клиент вводит точные значения.

### 9.4 Превью (Nano Banana 2.1, 1K)

Референсы: очищенное фото + до 8 картинок товаров.
Промпт: сохранить перспективу, свет, стены, окна; расставить конкретные товары в указанных позициях; фотореализм; без текста и людей.
3 варианта = 3 разные расстановки одного и того же набора.
Пост-обработка: водомарка «Верстакофф» (логотип с сайта, fallback — текст), WebP + JPEG.

### 9.5 Правки

1. Jev классифицирует текст: `add | remove | replace | color | layout | quantity | budget | other`.
2. LLM (structured output) меняет `selection_items` и/или `layout`.
3. Пересчёт суммы и проверка лимитов.
4. Перегенерация 2 вариантов от последнего согласованного превью.
5. Максимум 4 раунда; дальше — «Достигнут лимит правок».

### 9.6 Финал

- 4K из согласованного превью: `image_resolution: 4K`, референс — превью.
- Без водомарки.
- PDF: A4, логотип, номер и дата, клиент, параметры помещения, картинка 4K, таблица товаров (модель, артикул, габариты, кол-во, цена), итог, условия, контакты, «не является публичной офертой».
- Шрифт с кириллицей — `infra/assets/fonts/DejaVuSans.ttf`.
- PDF генерируется в worker, кладётся в MinIO, ссылка в `orders`.

## 11. Frontend

React 19 + Vite + React Router + TanStack Query + Tailwind. Дизайн — индустриальный, по мотивам werstakoff.ru: тёмно-серый, белый, акцент синий/оранжевый, крупные фото, минимум декора.

Маршруты:
- `/` — лендинг + старт.
- `/login`, `/register`.
- `/project/:id` — мастер (степпер): фото → проверка → очистка → размеры → вопросы → подбор → превью → правки → финал.
- `/project/:id/result` — заказ, 4K, PDF.
- `/account` — проекты, заказы, удаление данных.
- `/admin` — логин, статистика, сессии, заказы, каталог, настройки.

Состояние шага — из `GET /projects/:id`; прогресс — SSE. На каждом шаге видно, что происходит и сколько примерно займёт.

## 12. Приватность и хранение

- Фото и рендеры — 1 год, затем ежедневный cron удаляет.
- Заказы остаются; при удалении аккаунта обезличиваются (email → hash).
- Кнопка «Удалить мои данные» — удаляет фото, рендеры, проекты; заказы остаются.
- Внешние ссылки на файлы — только подписанные, TTL 1 час.
- Не логировать содержимое фото и персональные данные.
- Согласие на обработку — чекбокс при регистрации.

## 13. Правила разработки

- TypeScript strict, `noUncheckedIndexedAccess`, ESM, Node 22.
- Валидация всех входов — zod.
- Деньги — целые рубли (`price_rub`), не float.
- Размеры — целые миллиметры.
- Все AI-промпты — в `packages/ai/prompts/*.ts`, версионируются, не размазаны по коду.
- Никаких прямых вызовов fetch к Polza вне `packages/ai/client.ts`.
- Идемпотентность: job key = `{projectId}:{step}:{version}`.
- Ошибки AI не глотать: статус `failed`, причина в `ai_jobs`, пользователю — понятный текст.
- Секреты только в `.env`; `.env.example` обновлять при добавлении переменных.
- Тесты не пишем (решение заказчика). Перед сдачей: `pnpm typecheck`, `pnpm lint`, `docker compose build`, ручной happy-path.
- Коммиты: `feat:`, `fix:`, `chore:`, `docs:`.

- Обновление: `git pull --ff-only && docker compose build && docker compose up -d`; миграции Prisma применяются автоматически.
- Бэкап: `pg_dump` + tar volume `constructorai_storagedata` по cron (см. DEPLOY.md §12).
